## Ограничения

- ML-артефактов в исходном FraudBanc нет; CatBoost и полная аналитика на новом backend пока не подключены.
- При первом тестовом запуске sandbox не разрешил открыть системный временный каталог pytest. Скрипт целевого проекта использует уникальный рабочий `.test-tmp` для каждого прогона. Windows sandbox всё равно ограничивает каталоги, создаваемые pytest с mode 0700, поэтому успешный целевой прогон выполнен с разрешённым доступом. Временные каталоги тестов исключены из Git.
- Исходные проекты сохранены; для новой системы используется отдельная SQLite. Перенос существующего рабочего баланса из исходной базы автоматически не выполняется.
- Docker и браузерная визуальная проверка на этом этапе не выполнялись.

## Приёмка этапа 4

- Реальный перевод оценивается сервером; высокий риск -> pending_approval назначенному родственнику, отсутствие активного доверенного лица -> blocked_no_trusted. Оба состояния без списания. Настройки уведомлений/подтверждения не обходят антифрод.
- Отдельная TransferRequest фиксирует сумму, получателя, карты, снимок риска/версии политики и решение. Approve/reject/cancel с проверкой прав, срок 24 часа, повторная проверка средств и семейной связи. Денежные проводки и состояние атомарны, дубли не списывают повторно.
- AMAN показывает ожидание, блокировку, причины, собственные запросы и очередь родственника. Прежние приглашения сохранены. Браузерная визуальная проверка недоступна; node --check и Node VM проверки прошли.
- Независимый обзор принят. Общий прогон **122 passed** (100.51 с), последний новый сценарий отдельно **1 passed** (1.19 с); текущая коллекция **123**. Сохранён прежний денежный набор с явно изолированной политикой в трёх модулях; новые проверки используют реальный антифрод.
- HTTP-сценарий на отдельной временной SQLite подтвердил бабушка -> pending -> сын approve -> единственное списание/зачисление, sender403 и приватность. Рабочая база не менялась; сервер остановлен.
- Ограничения прототипа: нет резервирования, истечение при обращении, списки запросов без пагинации, SQLite сериализует операции; кабинет аналитика и полные batch workflows ещё не перенесены. Следующий этап — 5.
