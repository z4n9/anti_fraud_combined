## Ограничения

- ML-артефактов в исходном FraudBanc нет; CatBoost и полная аналитика на новом backend пока не подключены.
- При первом тестовом запуске sandbox не разрешил открыть системный временный каталог pytest. Скрипт целевого проекта использует уникальный рабочий `.test-tmp` для каждого прогона. Windows sandbox всё равно ограничивает каталоги, создаваемые pytest с mode 0700, поэтому успешный целевой прогон выполнен с разрешённым доступом. Временные каталоги тестов исключены из Git.
- Исходные проекты сохранены; для новой системы используется отдельная SQLite. Перенос существующего рабочего баланса из исходной базы автоматически не выполняется.
- Docker и браузерная визуальная проверка на этом этапе не выполнялись.

## Приёмка этапа 4

- Реальный перевод оценивается сервером; высокий риск -> pending_approval назначенному родственнику, отсутствие активного доверенного лица -> blocked_no_trusted. Оба состояния без списания. Настройки уведомлений/подтверждения не обходят антифрод.
- Отдельная TransferRequest фиксирует сумму, получателя, карты, снимок риска/версии политики и решение. Approve/reject/cancel с проверкой прав, срок 24 часа, повторная проверка средств и семейной связи. Денежные проводки и состояние атомарны, дубли не списывают повторно.
- AMAN показывает ожидание, блокировку, причины, собственные запросы и очередь родственника. Прежние приглашения сохранены. Браузерная визуальная проверка недоступна; node --check и Node VM проверки прошли.
- Независимый обзор принят. Общий прогон **122 passed** (100.51 с), последний новый сценарий отдельно **1 passed** (1.19 с); текущая коллекция **123**. Сохранён прежний денежный набор с явно изолированной политикой в трёх модулях; новые проверки используют реальный антифрод.
- HTTP-сценарий на отдельной временной SQLite подтвердил бабушка -> pending -> сын approve -> единственное списание/зачисление, sender403 и приватность. Рабочая база не менялась; сервер остановлен.
- Ограничения прототипа: нет резервирования, истечение при обращении, списки запросов без пагинации, SQLite сериализует операции; кабинет аналитика и полные batch workflows ещё не перенесены. Следующий этап — 5.

## Этапы 6.2–6.4 — реализация, 8 октября 2026

Пользователь одобрил несколько родственников, антискам-вопросы и банковские события в Risk Ledger; при конфликте родственников решает сотрудник банка. - До трёх additive приглашений с Mock eGov и личным согласием. Удаление адресное, с прежним ожиданием 24 часа. Остальные родственники сохраняются.
- Frozen TransferParticipant, неизменяемые голоса, ожидание всех ответов, unanimous approve/reject и bank_review при конфликте. Изменение состава после создания не уменьшает исходный кворум. Одобрение сотрудника не обходит незавершённые голоса и утраченные полномочия.

## Этап 6.1 — выборочный перенос защиты от быстрого отключения

- Реализованы сохранённые заявки disable/remove, ожидание 24 часа, собственная история и отмена. Повтор не переносит срок; частичный индекс защищает от дублирования. Снимок приглашения не позволяет прежнему удалению затронуть новую связь.
- Действующая защита не ослабляется до срока. Уведомления независимы; отключение подтверждения при активной защите и замена принятого родственника без удаления отклоняются. Денежный путь и полномочие родственника сохранены.
- Due lifecycle фиксируется до команд и повторно проверяется при получении блокировки: отказ финансовой команды не возвращает истёкшее полномочие. После отключения принятое приглашение сохраняется; явное включение может восстановить его для ещё ожидающих неистёкших переводов. Удаление очищает назначение.
- AMAN показывает дату, состояние и отмену; после действий перечитывает сервер. node --check и transient Node VM проверки прошли. Независимый security review принят без блокеров.
- HTTP smoke на отдельной SQLite подтвердил создание/повтор/отмену, сохранение защиты до срока, запрет мгновенной замены, удаление после срока и blocked_no_trusted без изменения денег. Для имитации истечения менялся только срок в изолированной smoke-базе; сервер остановлен.
- Прежние тесты немедленного выключения и замены адаптированы к новой политике с сохранением денежных проверок. Первый прогон: 264 passed, 7 skipped и один старый сценарий немедленного выключения failed. После его адаптации окончательный полный прогон: **265 passed, 7 skipped, 1 предупреждение Starlette/httpx, 210.18 с**. Исходные проекты и рабочая банковская база не менялись.

## Исправление загрузки больших CSV — 9 октября 2026

HTTP detail сохраняется в UI вместо ложного сообщения о недоступности сети. Финансовая политика и лимиты 500 МиБ / 1 000 000 записей не изменены.
