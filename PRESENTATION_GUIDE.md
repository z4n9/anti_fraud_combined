# Руководство по запуску и презентации AMAN Bank + Risk Ledger

**Версия: конкурсный MVP v1.0.0** (обновлено 8 октября 2026). Документ для выступления на конкурсе по борьбе с мошенничеством: что это, как запустить через Docker, что показывать, что говорить и о чём честно предупредить жюри.

Связанные файлы: [DEPLOYMENT.md](DEPLOYMENT.md) — сервер, порты, HTTPS, резервные копии; [USER_GUIDE.md](USER_GUIDE.md) — подробная инструкция по экранам; [docs/mvp-release.md](docs/mvp-release.md) — состав и границы релиза.

---

## 1. Идея в одной минуте

**Проблема.** Мошенники убеждают человека, чаще пожилого, самому перевести деньги. Банк видит «законный» перевод от настоящего владельца карты и обычно бессилен.

**Решение — три линии защиты в одной системе:**

1. **Семья решает.** Если перевод выглядит опасно, деньги **не списываются**, пока по этому конкретному переводу не ответят **назначенные родственники** (до трёх). Отправитель одобрить его сам не может.
2. **Банк разбирает конфликты.** Если родственники разошлись во мнении, или клиент ответил тревожно на вопросы AntiScam, решение принимает **сотрудник банка** в Risk Ledger. Он обязан указать основание, а система записывает, кто и когда решил.
3. **Аналитик ищет схемы.** В Risk Ledger можно загрузить выгрузку операций, получить ранжирование подозрительных переводов с объяснениями на русском языке и зафиксировать итог расследования.

**Чем отличаемся от обычного антифрода:**
- Решает **доверенный человек**, а не только алгоритм или SMS-код на телефон, который получает тот же обманутый клиент.
- Право родственника ограничено **одним переводом**: он не видит баланс и историю и не может распоряжаться деньгами.
- Каждая тревога **объяснима**: «крупная сумма новому получателю», а не «модель выдала 0,87».
- Без родственника рискованный перевод **не проходит автоматически**.
- Защиту нельзя быстро снять под давлением мошенника: отключение занимает **24 часа**.
- Единственное исполнение: деньги, статус и журнал решений меняются **одной неделимой операцией**.

> Всё в демонстрации тестовое: люди, ИИН, деньги и родство вымышлены. Реальные банки, SMS и eGov не подключены.

## 2. Подготовка к показу

### 2.1 Рекомендуемый способ: Docker (один контейнер, оба интерфейса)

**Что нужно на компьютере:** Docker Desktop (Windows, режим Linux containers) или Docker Engine с Compose. Ни Python, ни Node, ни соседние папки проекта не нужны. Всё собирается внутри образа.

Из корня `anti_fraud_arrt`, PowerShell:

```powershell
docker compose up --build -d --wait
docker compose ps
```

Первая сборка требует интернет. После неё запуск работает без интернета.

| Что | Адрес |
|---|---|
| Банк клиента AMAN | http://127.0.0.1:8000/ |
| Кабинет Risk Ledger | http://127.0.0.1:8000/analyst/ |
| Готовность обоих модулей (ожидается `status: ok`) | http://127.0.0.1:8000/api/readiness |
| Документация API (для технических вопросов) | http://127.0.0.1:8000/docs |

Остановка: `docker compose down` (данные сохраняются). **Не используйте** `down -v` на основной базе: оно удаляет данные.

**Данные** хранятся в отдельном постоянном томе Docker. Перезапуск и пересоздание контейнера ничего не сбрасывают.

### 2.2 Репетиция на отдельной базе (обязательно перед выступлением)

Каждый прогон сценария меняет балансы и согласия. Для чистой репетиции используйте **новое имя проекта** — оно создаёт новый пустой том с начальными тестовыми данными:

```powershell
$env:AMAN_PORT='8001'
docker compose -p aman-rehearsal-01 up -d --wait
```

Откройте http://127.0.0.1:8001/. Для следующей репетиции возьмите новое имя (`aman-rehearsal-02`). Остановка: `docker compose -p aman-rehearsal-01 down`.

**Перед выступлением** поднимите «боевой» проект с новым именем, например `aman-show`, на порту 8000 и сразу пройдите там только вход, чтобы не «тратить» баланс Амины:

```powershell
$env:AMAN_PORT='8000'
docker compose -p aman-show up -d --wait
```

Если демонстрация всё же прошла и нужно повторить, самый простой путь — `docker compose -p aman-show down -v` (удаляет **только данные этого демонстрационного проекта**) и новый `up`.

### 2.3 Автоматическая проверка перед выходом (по желанию)

На репетиционной базе, нужен Python 3.12+:

```powershell
python scripts/smoke_demo.py --base-url http://127.0.0.1:8001 --confirm-demo-writes --state-out .test-tmp/rehearsal-state.json
```

Скрипт проходит весь сценарий сам: два согласия, конфликт, решение сотрудника, одно списание, AntiScam, загрузка CSV, роли. Если он прошёл, система в рабочем состоянии. **Не запускайте его на боевой базе показа.**

### 2.4 Запуск без Docker (запасной вариант)

Нужны Python с окружением `test_env` рядом с проектом и собранный кабинет (`frontend\analyst\dist`):

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Адреса те же, кроме `/api/readiness`. Остановка: `Ctrl+C`. Состояние хранится в `aman_bank.db` и **не сбрасывается** при перезапуске; не подменяйте его копией поверх работающего сервера. Подробнее — в [README.md](README.md).

### 2.5 Запасной план на случай «нет интернета, нет Docker на чужом ноутбуке»

Сохраните образ заранее и возьмите его на флешке вместе с `compose.yaml`:

```powershell
docker save -o aman-bank-mvp-1.0.0.tar aman-bank-mvp:1.0.0
```

На другом компьютере с Docker:

```powershell
docker load -i aman-bank-mvp-1.0.0.tar
docker compose up -d --no-build --wait
```

Архитектура должна совпадать (проверенный образ — linux/amd64). Интернет и сборка не нужны. Всегда имейте также **запись экрана** с полным сценарием.

### 2.6 Два независимых окна браузера (критично)

Нужны **независимые сессии**: обычное окно и окно инкогнито **плюс** второй браузер или профиль. Несколько окон одного инкогнито делят одну сессию, и вход в новый аккаунт выкинет предыдущий.

Для главного сценария нужны **три роли одновременно:**

| Окно | Кто |
|---|---|
| 1 (обычное) | Амина — отправитель |
| 2 (инкогнито) | Марат — родственник № 1 |
| 3 (другой браузер или профиль) | Сауле — родственник № 2, затем сотрудник банка |

Если профилей мало, действуйте последовательно: входить и выходить в одном окне допустимо, это просто медленнее.

## 3. Часть A — AMAN Bank: функции простыми словами

### A1. Вход и безопасность
**Показать.** Войти как Амина.
**Сказать.** Пароли хранятся только в защищённом виде (scrypt с солью). Сессия лежит на сервере, в браузер идёт случайный токен в защищённой cookie, недоступной скриптам; срок 12 часов, выход отзывает сессию. Каждый видит **только свои** карты и историю.

### A2. Карта, баланс и история
**Сказать.** Деньги внутри хранятся **целыми тиынами**, а не дробными числами: ошибок округления нет.

### A3. Обычный перевод по телефону
**Показать.** Алихан → «Переводы» → «По номеру телефона» → `+77010000043` → `1000` → подтвердить. Перевод проходит сразу.
**Сказать.** Перед каждым переводом **сервер сам** оценивает риск; подмена запроса в браузере ничего не даёт. Списание, зачисление и записи истории происходят одной неделимой операцией; овердрафт невозможен; повторная отправка формы не спишет деньги дважды.

### A4. Семейная защита: до трёх родственников
**Показать (Амина + Марат + Сауле):**
1. Амина → «Семейная защита» → «Настройки защиты» → включить → сохранить.
2. «Добавить доверенное лицо» → `TEST0003` → «Проверить родство» → «Отправить приглашение».
3. Повторить для `TEST0007` (Сауле). Ожидающее приглашение тоже занимает одно из трёх мест.
4. Марат и Сауле, каждый в своём окне: уведомления → входящие приглашения → «Принять».
5. У Амины обновить экран: «Защита активна».

**Сказать.** Родство проверяет реестр (в демо — его имитация), а не слова клиента. Родственник соглашается **сам из своего аккаунта**: назначить человека «втёмную» нельзя. **Отрицательный пример:** проверка `TEST0005` из аккаунта Амины вернёт «родства нет».

### A5. Вопросы AntiScam при переводе
**Что это.** Три вопроса в форме перевода: на вас давят? Просят хранить перевод в тайне? Вами руководит незнакомец?
**Важно сказать.**
- Пропущенный ответ означает **«не знаю»**, а не «нет».
- Ответ «Да» **не списывает** деньги и ведёт к проверке сотрудником банка.
- Ответы сохраняются вместе с запросом; изменить их можно только новым запросом.
- Если при высоком риске ответы тревожные, сначала голосуют родственники, затем решает банк.

### A6. ГЛАВНЫЙ СЦЕНАРИЙ: семья и банк вместе
Так проходит почти вся демонстрация. Пройдите его на репетиции минимум дважды.

1. **Амина** создаёт перевод Айдане (`+77010000043`) на **`1000000.25` ₸** (от 80% до 100% баланса; при другом балансе подберите сумму сами). Ответы AntiScam — «Нет».
2. Статус: **«Ожидает решения родственников»**. Покажите: баланс Амины не изменился, у Айданы денег нет.
3. **Марат** → «Запросы на перевод» → «Решения для родственников»: видит отправителя, получателя, сумму, причины риска простым языком, срок. Нажимает **«Одобрить»**.
4. Деньги **по-прежнему на месте**: Сауле ещё не ответила. Молчание — не согласие.
5. **Сауле** **отклоняет** тот же запрос. Родственники разошлись, статус: **«Проверка сотрудником банка»**. Списания всё ещё нет.
6. **Сотрудник банка (`TEST0099`)** → Risk Ledger → «Банковские события» (файл загружать не нужно). Открывает запрос: сумма, получатель, причины риска, ответы AntiScam, **голоса обоих родственников**. Вводит основание (5–500 символов), например «Клиент подтвердил по телефону, получатель — дочь знакомой», и нажимает «Одобрить» или «Отклонить».
7. При одобрении **один раз** списывается у Амины и зачисляется Айдане; в карточке остаются сотрудник, основание, время. При отказе деньги остаются у Амины. Обновите баланс и историю обоих.

**Что сказать:**
- Без единогласия деньги не двигаются. Единогласное «да» всех родственников исполняет перевод (если нет тревожных ответов AntiScam), единогласное «нет» отклоняет, разногласие уходит банку.
- Отправитель **не может** одобрить собственный запрос.
- Состав голосующих **фиксируется при создании перевода**. Нового родственника на старый запрос не добавить; удаление родственника не уменьшает число нужных голосов.
- Сохранённый голос изменить нельзя.
- Родственник не видит баланс и историю Амины, только детали этого запроса.
- Сотрудник решает **только** запросы, переданные на банковскую проверку. Он не может обойти незавершённое семейное голосование, истёкший срок или отсутствие доверенного лица.
- Запрос действует **24 часа**, включая банковскую проверку. Отправитель может его отменить.

**Короткий вариант (если времени мало):** один родственник одобряет — перевод исполняется (при одном родственнике порядок прежний и проще).

### A7. Высокий риск без родственника
**Показать.** Алихан (без защиты) отправляет Айдане от 80% баланса (например `2400000`). Результат: **«Не исполнен: нет активного доверенного лица»**, деньги не списаны.
**Сказать.** Опасный перевод без «второго ключа» автоматически не проходит. Механизм для таких случаев (пауза, звонок, ручная проверка) ещё проектируется.

### A8. Защита от быстрого отключения
**Показать.** Амина → «Отключить защиту (через 24 часа)»; для конкретного родственника — кнопка «Удалить родственника (через 24 часа)». Появляется дата вступления в силу, защита **продолжает работать**, заявку можно отменить.
**Сказать.** Классический приём мошенника — «сначала отключите защиту». Мы дали клиенту сутки опомниться, а родственникам узнать. Удаление адресное: остальные родственники сохраняются.

### A9. Что в AMAN пока макет
Платежи за услуги, QR, пополнение, переводы по карте/IBAN/за границу, биометрия — демонстрационные экраны без денежных операций. **Работает перевод по телефону** между клиентами. Не нажимайте макеты на сцене.

### A10. Быстрые ответы по безопасности
- Запросы с чужих сайтов блокируются; ответы API не кэшируются.
- Файлы базы и исходники недоступны из браузера.
- Запрос, участники, суммы, карты, снимок оценки риска и ответы AntiScam фиксируются в отдельной записи: каждое решение прослеживается.
- Контейнер запускается не от администратора, с файловой системой только для чтения и без лишних привилегий.

## 4. Часть B — Risk Ledger: рабочее место банка

### B0. Что это
Кабинет специалиста по безопасности. В нём два рабочих потока:
1. **Банковские события** — живая очередь переводов из AMAN, требующих решения сотрудника.
2. **Анализ выгрузок** — загрузка файла с операциями и поиск подозрительных.

Система **ничего не блокирует сама** и не объявляет виновных. Главный принцип: **оценка риска — повод проверить, а не доказательство мошенничества.**

### B1. Вход
http://127.0.0.1:8000/analyst/ → `TEST0099` / `Aman-Test-0099!` (в отдельном окне).
**Сказать.** Отдельная роль. У сотрудника **нет карты** и доступа к чужим счетам, а клиент не может открыть кабинет. Каждый аналитик видит только свои анализы. Прямые ссылки на разделы работают и после обновления страницы.

### B2. «Банковские события» (связь с AMAN)
Это то место, где сотрудник завершает сценарий A6. Фильтр по статусу («Проверка банка» по умолчанию), по имени отправителя; для просмотра завершённых запросов поменяйте фильтр.
**Сказать.** Решение требует письменного основания; сервер сам записывает сотрудника и время; деньги, статус и аудит меняются атомарно. Повторное нажатие не списывает деньги второй раз.

### B3. Анализ выгрузки (второй поток)
1. «Новый анализ» → загрузить `examples/transactions_demo.csv` (7 операций: 6 обычных по 100 ₸ и одна на 100 000 ₸ новому получателю через минуту).
2. Система сама распознаёт поля (клиент, счёт, сумма, дата, получатель) и показывает понятный **план**. Если обязательные поля не распознаны уверенно, анализ **блокируется**: система не угадывает.
3. Запустить анализ. Разделы: **Обзор**, **Операции** (последняя ожидаемо с высоким сигналом), **Связи** (граф «кто кому переводил»), **Качество данных**.
4. В карточке записи — причины простыми словами с цифрами, без технических названий признаков.
5. Присвоить статус («Новое», «В работе», «Мошенничество подтверждено», «Риск не подтвердился») и комментарий, при необходимости экспортировать или удалить анализ.

**Форматы:** CSV, JSON/JSONL, SQL-выгрузки, SQLite, BSON (до 500 МБ и 1 000 000 записей). Файл только читается, SQL не исполняется как скрипт. Загруженные данные **не меняют** счета и банковскую историю.

**11 сценариев поиска:** необычно крупная сумма, всплеск частоты за день, серия переводов за минуты, дробление суммы, новый получатель, ночная активность, много отправителей одному получателю, циклические переводы, быстрый вывод поступивших денег, активность после долгого простоя, отклонение от обычного поведения клиента.

### B4. Что важно сказать о методе
- **Правила и граф связей, без «чёрного ящика»**: понятно, почему сработала тревога.
- Используется только то, что было **до** операции (никакого «подглядывания в будущее»).
- Риск получателя, риск самой операции и **неопределённость** (мало истории) показываются **отдельно**. Нехватка данных не делает человека виноватым.
- **Один и тот же движок** защищает переводы в AMAN и анализирует выгрузки в Risk Ledger.

## 5. Общая картина (для слайда)

```
Клиент AMAN → перевод (+ ответы AntiScam) → сервер оценивает риск правилами и графом
  ├─ низкий/средний риск, ответы спокойные → деньги идут сразу
  ├─ высокий риск + есть родственники → голосуют все: ждут, деньги на месте
  │     ├─ все «да» (и нет тревожных ответов) → исполняется
  │     ├─ все «нет» → отклонено
  │     └─ разногласие / тревожные ответы → сотрудник банка решает с основанием и аудитом
  └─ высокий риск + нет родственников → перевод не исполняется

Risk Ledger → «Банковские события» (решения) + анализ выгрузок (поиск схем) → решение человека
```

## 7. Честно о границах (скажите сами, это повышает доверие)

- Антифрод сейчас на **объяснимых правилах и графе, без машинного обучения**: обученных моделей нет, система сама заявляет `rule_based_fallback`. ML подключим после проверки данных и артефактов.
- Процент в Risk Ledger — **приоритет проверки**, а не вероятность мошенничества. Качество правил на реальном банковском датасете **не оценено**.
- Деньги **не резервируются** на время ожидания: если их потратить другой операцией, при одобрении может не хватить.
- Сроки проверяются при запросах к серверу; **фонового таймера нет**.
- Одна SQLite и один процесс: это конкурсный демонстрационный MVP, а не промышленная система; масштабирование на несколько процессов не поддерживается.
- Реальные eGov, SMS, внешние уведомления, платёжные сети и банки **не подключены**. Сообщения и поддержка клиентов — в планах.
- Для случая «высокий риск, но родственников нет» отдельная процедура проверки (пауза, звонок, ручная проверка) ещё проектируется.
- Публикация в интернете **не выполнена**: релиз готовит переносимый Docker-образ и конфигурацию (запуск на сервере с HTTPS описан в DEPLOYMENT.md). Пароли публичные, реальные данные загружать нельзя.
- **Визуальная проверка в браузере в рамках разработки не проводилась** (программные и HTTP-проверки есть). Пройдите сценарий вручную до выступления.

**Что подтверждено проверками (из документации проекта):** backend — 330 тестов прошли, 7 пропущены (необязательные); интерфейс аналитика — 62 теста, проверка стиля и сборка прошли; Linux-образ собран, сквозной сценарий (два родственника и сотрудник) прошёл; после пересоздания контейнера сохранились деньги, голоса, решение сотрудника и анализ; резервная копия и восстановление данных проверены. Версия зафиксирована в Git как `v1.0.0-mvp`. Я эти прогоны сам не повторял.

## 8. Вероятные вопросы жюри

**Что, если родственник сам мошенник?** Родство подтверждает реестр, согласие даёт сам родственник. Решает только отдельные переводы, к счёту доступа нет. При нескольких родственниках нужен единогласный ответ, а при разногласии решает банк.

**Что, если родственники не отвечают?** Запрос живёт 24 часа, затем перестаёт быть исполнимым; отправитель может отменить его раньше. Молчание — не согласие.

**Что, если клиенту срочно?** Срочность — типичный приём мошенников, поэтому опасный перевод ждёт. Процедура на исключительные случаи в проектировании.

**Чем отличается от SMS-подтверждения?** SMS получает тот же человек, которого обманывают. Решает **другой** человек, а в спорных случаях банк.

**Почему не нейросеть?** Правила объяснимы клиенту, аналитику и регулятору. ML добавим как дополнительный сигнал после проверки на реальных данных.

**Можно ли обойти проверку через интерфейс?** Нет. Риск считает сервер; права отправителя, родственников и сотрудника проверяются на сервере; повторная отправка не списывает дважды.

**Как защищён банковский ответ сотрудника?** Обязательное основание, сервер сам записывает сотрудника и время, решение нельзя применить к запросу, который ещё ждёт семью или уже истёк.

**Как это развернуть?** Один Docker-контейнер с обоими интерфейсами, данные в отдельном томе, готовность проверяется `/api/readiness`, образ можно перенести файлом без интернета.

**Какие данные использует?** Только историю самого банка и тестовые файлы. Данные не покидают компьютер.
