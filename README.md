# Family Bank и Family Guard

С 4 ноября 2026 банковские переводы используют встроенную **LightGBM S0_CLEAN, адаптированную в KZT из anti_fraud_1**, вместе с правилами и графом (ADR-020/021). Модель и зависимости включены в Docker, соседний проект при запуске не нужен. Достаточно первого ответа одного из до трёх родственников; пароли-имена сохранены.


Вся документация в Word, презентация и one pager RU/EN собраны в [единый ZIP-комплект](contest/Family_Bank_Family_Guard_Documents.zip). После распаковки откройте `00_START_HERE.docx` внутри папки комплекта.

Для конкурса: [центральное техническое приложение в Word](docs/technical-appendix/00-index.docx) — методика, данные и исходники, проверки и тест-кейс, план доработки и TRL. [Исходники и список разделов](docs/technical-appendix/README.md).

Конкурсный MVP **v1.0.0**: клиентский Family Bank, проверка риска правилами и графом, до трёх доверенных родственников, AntiScam и кабинет Family Guard. С 4 ноября 2026 достаточно первого ответа одного из назначенных родственников: одобрение разрешает исполнение, отказ отклоняет перевод; тревожный AntiScam требует проверки банка. Редакция от 15 октября 2026 включает добровольную семейную защиту и мониторинг получателей; сообщения, внешние уведомления и обучение ML относятся к возможным следующим версиям.

Названия и сохраняемые технические идентификаторы: [docs/branding.md](docs/branding.md).

Все люди, ИИН, счета и деньги демонстрационные. Приложение не выполняет реальные банковские операции и использует Mock eGov. Результаты проверок — [docs/testing.md](docs/testing.md).

## Быстрый запуск готового MVP через Docker

Установите и запустите Docker Desktop либо Docker Engine с Compose. Из корня **этого** репозитория:

```powershell
docker compose up --build -d --wait
docker compose ps
```

Откройте **http://127.0.0.1:8000/** и **http://127.0.0.1:8000/analyst/**. Docker собирает кабинет сам; Python, Node и соседние исходные проекты на компьютере не нужны. Первый запуск создаёт тестовые аккаунты в отдельном постоянном Docker-томе. Локальный `aman_bank.db` в образ не копируется. Проверка готовности обоих модулей: `/api/readiness`.

Остановка: `docker compose down`. Повторный запуск сохраняет данные. **Не добавляйте `-v`**, если нужно сохранить том. Настройка порта, HTTPS, резервные копии и перенос на сервер — [DEPLOYMENT.md](DEPLOYMENT.md). Для первой сборки нужен интернет; готовый образ можно перенести для офлайн-показа.

Для презентации: [PRESENTATION_GUIDE.md](PRESENTATION_GUIDE.md). Учётные данные и инструкции для клиента/родственника/сотрудника — [USER_GUIDE.md](USER_GUIDE.md).

Готовые конкурсные файлы: [презентация PowerPoint на 12 слайдов](contest/Family_Guard_Pitch_Deck.pptx), [резюме RU](contest/Family_Guard_Summary_RU.docx), [резюме EN](contest/Family_Guard_Summary_EN.docx). Оформление и подготовка к выступлению — [contest/README.md](contest/README.md).

Пошаговое руководство, полный список тестовых телефонов и сценарии семейной защиты: [Инструкция пользователя](USER_GUIDE.md).

В кабинете аналитика добавлен [мониторинг небольших поступлений](docs/recipient-monitoring.md): банковская история или завершённая выгрузка, получатели, новые отправители и объяснение сигнала. ## Запуск банковской части

Из `anti_fraud_arrt`:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт использует `.venv\Scripts\python.exe`, а при его отсутствии — подготовленное окружение `..\test_env\Scripts\python.exe`. Для разработки можно добавить `-Reload`; для другого локального порта — `-Port 8001`.

На новом компьютере создайте окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Откройте приложение: **http://127.0.0.1:8000**. Swagger: **http://127.0.0.1:8000/docs**. Диагностика: **http://127.0.0.1:8000/api/health**. FastAPI раздаёт клиентский интерфейс вместе с API.

Прямой запуск:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Проект использует локальные учебные аккаунты, вымышленные деньги и Mock eGov. Реальные банковские сервисы не подключены.

## База данных и переводы

Новая система хранит собственную SQLite в `anti_fraud_arrt/aman_bank.db`. Исходные проекты не используются как runtime-зависимости. Существующая исходная база автоматически не копируется. `AMAN_DATABASE_URL` позволяет явно выбрать другую базу; не направляйте его на исходные проекты для обычной проверки.

Миграция сохраняет существующие банковские данные и делает резервную копию перед добавлением столбцов. Деньги хранятся целыми тиынами. Списание, зачисление и обе записи истории сохраняются одной транзакцией. Seed сохраняет балансы и пользовательские пароли; прежние стандартные пароли восьми демо-аккаунтов обновляются на имена из таблицы выше.

`POST /api/transfers` требует сессию и заголовок `Idempotency-Key` (1–100 символов, непустой). Для каждого нового перевода нужен новый ключ; для повтора того же запроса — прежний. Ключи изолированы по отправителям. Family Bank UI уже передаёт этот заголовок. Поддерживаются переводы между тестовыми клиентами по номеру телефона; другие способы пока макеты.

## Перевод и семейное решение

Команда `POST /api/transfers` рассчитывает риск на сервере. Семейная защита добровольна: если она выключена, high/critical показывает предупреждение и рекомендацию подключить родственников. Явное действие «Перевести, понимая риск» передаёт строгий bool `risk_warning_acknowledged=true`; без подтверждения сервер возвращает HTTP 428 без списания. При включённой защите высокий риск создаёт `pending_approval` для согласившихся родственников; отсутствие действующего семейного согласия даёт `blocked_no_trusted`. Тревожный AntiScam сохраняет отдельный `bank_review`. Политика — ADR-016.

Запрос фиксирует получателя, сумму, сообщение и выбранные карты. Отправитель может отменить ожидание, но не одобрить собственный запрос. Родственник может одобрить или отклонить только назначенную операцию. Сервер повторно проверяет полномочия, текущую семейную связь и средства; повторное одобрение не списывает дважды. При изменении реквизитов требуется новый запрос. Срок ожидания — 24 часа; средства не резервируются, поэтому более позднее одобрение может не пройти из-за недостаточного баланса.

`GET /api/transfers/requests` показывает собственные запросы, `GET /api/transfers/pending-requests` — очередь родственника. Действия: `POST /api/transfers/requests/{id}/approve`, `/reject`, `/cancel`. ID запроса отличается от ID выполненной проводки. Для нового запроса нужен новый `Idempotency-Key`; повтор старого ключа возвращает сохранённое состояние, в том числе отказ или ожидание.

Уведомления на этом этапе отображаются внутри Family Bank. SMS, email и внешние банковские сервисы не подключены.

## Предварительная проверка риска

После входа вызовите `POST /api/transfers/risk-check` через Swagger или из клиента с той же сессией:

```json
{"recipient": "+77010000043", "amount": "1000.00"}
```

Укажите телефон существующего тестового получателя и сумму в пределах баланса. Сервер определяет отправителя и время проверки сам. Ответ содержит `recipient_risk`, `transaction_risk`, `data_uncertainty`, объяснения факторов, `overall_level`, а также `family_protection_active` и `requires_risk_acknowledgement`. Сейчас `engine_mode=rule_based_fallback`, `advisory=true`, `transfer_enforcement=false`. Проверка не списывает деньги и не записывает предполагаемый перевод в историю; обязательный ключ нужен только команде перевода. Family Bank вызывает preview перед подтверждением, а сервер команды повторно проверяет риск и настройки под блокировкой.

Используется завершённая внутренняя история строго раньше момента проверки. Зеркальные списание и зачисление дают одно ребро графа. Недостаток истории отражается отдельно и не уменьшает риск. Ночные операции определяются по UTC+5. Читаются последние 50 000 общих операций; усечение отмечается в неопределённости. Справочники карт и клиентов пока читаются целиком.

Онлайн-проверка использует LightGBM, защитные правила и граф. Отдельный файловый анализ в кабинете поддерживает доверенные локальные артефакты IsolationForest и работает по правилам и графу при их отсутствии. Клиент не выбирает файл модели. Клиентская ML-модель кабинета требует отдельных зависимостей и доверенных артефактов. Публичный банковский API объясняет сработавшие правила без чужих персональных данных. Пороговые значения демонстрационные, качество на реальных данных не оценено.

## Кабинет аналитика Family Guard

Кабинет размещён на **http://127.0.0.1:8000/analyst/** и использует тот же backend. Отдельный тестовый доступ: **TEST0099 / `analyst`**. У аналитика нет банковской карты и права выполнять клиентские операции; клиентские аккаунты не имеют доступа к аналитическим API.

Перед первым запуском на новом компьютере установите frontend-зависимости и соберите кабинет из `anti_fraud_arrt`:

```powershell
npm.cmd ci --prefix frontend/analyst
powershell -ExecutionPolicy Bypass -File .\build-analyst.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

После изменения React-кода повторите сборку. Каталог `frontend/analyst/dist` не хранится в Git. Отсутствие сборки не мешает работе Family Bank; кабинет в этом случае временно недоступен.

Для первой проверки загрузите [examples/transactions_demo.csv](examples/transactions_demo.csv), проверьте план и запустите анализ. Доступны операции, связи, качество данных, ручные решения и экспорт. Форматы: CSV, JSON/JSONL, SQL-выгрузки, SQLite и BSON. По умолчанию лимиты — 500 МиБ и 1 000 000 записей; крупные объёмы на этом этапе не проверялись.

API кабинета — `/api/analyst`; вход общий `/api/auth/login`, проверка роли — `/api/analyst/me`. Каждый анализ принадлежит создавшему его аккаунту. Загрузка не изменяет банковскую историю и не даёт родственнику права одобрения. Для одновременной работы клиента и аналитика используйте независимые браузерные профили/сессии.

Транзакционный профиль работает без ML на правилах и графе. Процент сигнала — оценка приоритета проверки, а не вероятность мошенничества. Клиентский профиль без CatBoost-модели явно недоступен. Необязательные ML-зависимости описаны в `requirements-ml.txt`; установки пакета недостаточно — нужны отдельно проверенные доверенные артефакты. На этом этапе обучение не выполнялось.

Аналитические результаты хранятся в `runtime/risk_ledger`, модельные артефакты — в `artifacts/risk_ledger`; эти каталоги не публикуются веб-сервером. Миграция добавляет клиентам роль `client`, сохраняет балансы/пароли и создаёт резервную копию перед изменением столбцов. Аналитик создаётся отдельно без повышения прав существующих аккаунтов.

## Задержка отключения семейной защиты

Отключение активной защиты и удаление назначенного родственника выполняются через заявку с ожиданием 24 часа. До срока защита сохраняется; принятого родственника нельзя сразу заменить новым приглашением. Уведомления изменяются независимо. Отключение подтверждений отдельно при активной защите возвращает 409.

`GET /api/protection-change-requests` возвращает собственную историю. `POST` на тот же адрес принимает `{"action":"disable"}` или `{"action":"remove"}`; повтор ожидающей заявки возвращает прежний ID и срок. `POST /api/protection-change-requests/{id}/cancel` отменяет только собственную ещё не исполненную заявку. Сервер определяет сроки и статусы сам, посторонние поля отклоняются.

Таблица `protection_change_requests` хранит действие, владельца, снимок приглашения и даты создания/исполнения/решения. Исполнение применяется при обращении к семейным API и при проверке/команде перевода. Отдельного фонового worker нет. До фактического отключения сохраняются прежние семейные ограничения. После отключения новые переводы высокого риска доступны с предупреждением и явным подтверждением; старые запросы автоматически не исполняются. Семейные проводки остаются атомарными. UI и инструкция — [USER_GUIDE.md](USER_GUIDE.md).

## Несколько родственников, AntiScam и банковская проверка

Family Bank поддерживает до трёх верифицированных родственников с личным согласием. Состав доступных согласующих фиксируется для перевода. Первый ответ одного действующего родственника окончателен: одобрение исполняет перевод, если нет тревожного AntiScam, отказ отклоняет. Остальные родственники уже не отвечают. Добавление родственника не заменяет прежнего; адресное удаление сохраняет ожидание 24 часа и указывается через `invitation_id`.

Вопросы AntiScam сохраняют «Да», «Нет» и неизвестный ответ отдельно от численного риска. Тревожный ответ требует проверки банка; при высоком риске прежде отвечают родственники. Первый отказ родственника завершает запрос, отсутствие действующего родственника блокирует его.

В `/analyst/` сотрудник `TEST0099` получает раздел «Банковские события», доступный без загрузки файла и ML. API: `GET /api/analyst/bank-events`, детали `GET /{id}`, решения `POST /{id}/approve|reject` с обязательным `{ "note": "Основание решения" }` длиной 5–500 символов. Служебное решение допускается для банковской проверки; аудит и денежный журнал атомарны. Инструкция и демонстрация одного семейного ответа с AntiScam — разделы 13–15 [USER_GUIDE.md](USER_GUIDE.md).

## Режим банковского ML

- `AMAN_ML_MODE=auto` (по умолчанию): модель работает при исправных assets/зависимостях, иначе явно используется прежний rule_based_fallback.
- `AMAN_ML_MODE=required`: ошибка ML даёт503 без перевода; проверка готовности тоже503. Неизвестное значение режима не разрешает перевод.
- `AMAN_ML_MODE=off`: прежние правила и граф, без ML.

Статус модели доступен в `/api/health`, режим проверки и статус видны на предварительной оценке перевода. В «Банковских событиях» аналитик видит сохранённую оценку, решения, версию модели, OOD и денежные пороги в тенге. Баланс и внутренние признаки остаются в приватном аудите. При работающей модели порог 80% проверяется только после исходного `REVIEW`. При отключении модели или резервном переходе на правила этот порог применяется напрямую. Независимые правила и граф продолжают работать. Денежные признаки, деревья модели, OOD и правила используют KZT. Веса адаптированы по единицам измерения, качество на реальных KZT-платежах пока не подтверждено. Подробности — [ADR-020–023](docs/decisions.md).
