# Навык: Интеграция проектов (anti_fraud_1 + FraudBanc -> anti_fraud_arrt)

Этот навык определяет строгий, воспроизводимый регламент объединения двух независимых систем:
1. **anti_fraud_1**: банковский сервис переводов, авторизация (сессии + scrypt), проверка родства через Mock eGov, приглашение доверенного лица, мобильный web-интерфейс AMAN Bank.
2. **FraudBanc**: система анализа подозрительных операций и клиентов (Risk Ledger), правила транзакционного антифрода, граф связей, планировщик и React-интерфейс аналитика.

Цель: сформировать единый модульный backend на FastAPI и два согласованных интерфейса (клиентский AMAN и аналитический Risk Ledger) в репозитории `anti_fraud_arrt`.

---

## 1. Базовые принципы интеграции

1. **Не ломать работающее**: 32 теста `anti_fraud_1` (переводы, атомарность, идемпотентность, Mock eGov, приглашения) и тестовый набор `FraudBanc` должны оставаться зелёными.
2. **Модульность, а не монолитная склейка**:
   - `app/core`: конфигурация, безопасность, соединение с БД.
   - `app/domain`: канонические схемы, модели сущностей.
   - `app/bank`: логика пользователей, карт, переводов, Mock eGov и семейного подтверждения.
   - `app/antifraud`: правила проверки, граф транзакций, признаки, скоринг и адаптеры моделей.
   - `app/api`: маршруты банковских операций (`/api/transfers`, `/api/cards` и т.д.) и аналитического кабинета (`/api/analysis`, `/api/sources` и т.д.).
3. **Грациозная деградация (ML fallback)**: отсутствие весов моделей не должно блокировать проведение переводов или работу банковского API; включается детерминированный движок правил.
4. **Сначала каркас, затем сцепка**:
   - Шаг 1: перенос ядра данных, auth и базовых переводов.
   - Шаг 2: перенос аналитического модуля и адаптеров.
   - Шаг 3: точка перехвата перевода (pre-transfer risk check) и семейное подтверждение.
   - Шаг 4: сведение двух интерфейсов.

## 2. Пошаговый чек-лист переноса

### Этап 1. Подготовка каркаса и окружения
- [ ] Проверить структуру `anti_fraud_arrt`.
- [ ] Настроить виртуальное окружение Python (3.11-3.14) и объединённый `pyproject.toml` / `requirements.txt`.
- [ ] Проверить доступность зависимостей: `fastapi`, `uvicorn`, `sqlalchemy`, `pydantic`, `httpx`, `pytest`, `pandas`, `numpy`, `scikit-learn`.
- [ ] Создать базовую структуру папок: `backend/app/`, `frontend/`, `tests/`, `docs/`.

### Этап 2. Перенос банковского модуля (`anti_fraud_1`)
- [ ] Перенести модели данных: `User`, `Card`, `Transaction`, `TrustedPerson`, `MockCitizen`, `MockRelationship`, `TrustedInvitation`, `LoginSession`.
- [ ] Сохранить соглашение по хранению денег: целые тиыны в SQLite (`Integer`).
- [ ] Перенести механизм сессий, хеширования scrypt и cookie-авторизации.
- [ ] Перенести Mock eGov и жизненный цикл приглашений родственников.
- [ ] Запустить `pytest` для банковских сценариев — убедиться в 100% успехе.

### Этап 3. Перенос антифрод-модуля (`FraudBanc`)
- [ ] Перенести модуль транзакционных правил `transaction_rules.py` и `transaction_features.py`.
- [ ] Перенести генерацию синтетических транзакций и тестовые фикстуры.
- [ ] Реализовать сервис проверки перевода в реальном времени:
  - Вход: параметры текущего перевода (отправитель, карта, получатель, сумма, время).
  - Обработка: проверка по графу последних транзакций и сценариям (крупная сумма, всплеск частоты, структурирование, новый получатель, ночная активность).
  - Выход: уровень риска (`low`, `medium`, `high`, `critical`), детализированные факторы на русском языке.
- [ ] Добавить тесты на правила антифрода.

### Этап 4. Сцепка: семейное подтверждение при высоком риске
- [ ] Модифицировать эндпоинт `POST /api/transfers`:
  - Шаг 1: Валидация входных данных, поиск получателя.
  - Шаг 2: Оценка риска перевода антифрод-сервисом.
  - Шаг 3 (Низкий/средний риск): Немедленное атомарное списание и зачисление.
  - Шаг 4 (Высокий/критический риск):
    - Проверка наличия подтверждённого доверенного лица (`relationship_verified && invitation_status == 'accepted'`).
    - Если доверенного лица нет — отказ в авто-исполнении с пояснением.
    - Если доверенное лицо есть — создание записи перевода в статусе `pending_approval` без списания баланса.
    - Отправка уведомления/запроса родственнику.
- [ ] Реализовать эндпоинты подтверждения перевода доверенным лицом:
  - `GET /api/transfers/pending-requests` (только для доверенного лица).
  - `POST /api/transfers/{id}/approve` (только доверенное лицо; атомарное исполнение перевода).
  - `POST /api/transfers/{id}/reject` (отклонение; перевод переходит в `rejected`, баланс не списывается).
- [ ] Запретить отправителю самостоятельно подтверждать собственный рискованный перевод.

### Этап 5. Интерфейсы и сквозная верификация
- [ ] Обеспечить раздачу или проксирование AMAN Bank UI и Risk Ledger UI.
- [ ] Провести сквозной тест:
  - Бабушка отправляет подозрительный перевод.
  - Система требует подтверждения сына.
  - Сын в своём аккаунте подтверждает.
  - Деньги переводятся получателю.
